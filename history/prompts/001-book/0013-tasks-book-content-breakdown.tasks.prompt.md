## Prompt

Phase 3, Step 4: create the plan and tasks for the book content (feature:
001-book). We already have the spec, the chapter-authoring skill, and the
three subagents. Now produce the technical plan and the task breakdown.

## Part 1 — /sp.plan
Run the planning step for specs/001-book/spec.md. The plan should cover:
- Folder structure under book/docs/ for 4 modules + chapters (module folders,
  _category_.json for module order, chapter files with sidebar_position).
- The introduction page replacing the current placeholder intro.mdx.
- Module landing pages.
- The authoring workflow: chapter-writer drafts using the chapter-authoring
  skill, then code-verifier and consistency-checker review independently, then
  fixes are applied — per chapter.
- How the ROS-code execution gap is handled (this machine has no ROS 2; some
  examples can't be run here — the plan must state how those are marked).
- Build verification after each module (npm run build must stay green).
- Respect the constitution and the confirmed Jazzy/Harmonic/Ubuntu 24.04 target.

## Part 2 — /sp.tasks
Break the plan into tasks. Expected shape:
- One task per chapter (14 total), each including: write with skill, verify
  code, check consistency, apply fixes.
- Tasks for the 4 module landing pages and the introduction page.
- Tasks for _category_.json files and sidebar ordering.
- A build-check task after each module.
- Order tasks so Module 1 ships complete before Module 2 starts (per the
  spec's user-story priority).

## Constraints
- Do NOT write any chapter content yet — plan and tasks only.
- Keep tasks small and independently checkable.
- After both, summarize the plan approach and list the tasks in order.

## Summary at end
- The plan's key decisions
- The full ordered task list
- What the first chapter task will involve

*(This PHR covers Part 2. Part 1 is recorded in PHR 0012.)*

## Response snapshot

Ran `check-prerequisites.ps1` with `SPECIFY_FEATURE=001-book`; all four optional design docs were
found. Generated `specs/001-book/tasks.md` — **38 tasks, T001–T038**, in seven phases.

- Phase 1 Setup (T001–T003): verification log, baseline build, optional `trailingSlash`
- Phase 2 Foundational (T004–T005): rewrite `intro.mdx`, build check
- Phase 3 US1 Module 1 (T006–T012) 🎯 MVP
- Phase 4 US2 Module 2 (T013–T019)
- Phase 5 US3 Module 3 (T020–T026)
- Phase 6 US4 Module 4 (T027–T032)
- Phase 7 Polish (T033–T038)

**The per-chapter loop is defined once at the top** and referenced by all 14 chapter tasks, rather
than repeated 14 times: draft with `chapter-writer` → `code-verifier` and `consistency-checker`
launched together → fix blockers and majors → re-review only if a blocker was fixed.

**Decisions taken while breaking down the plan:**

1. **Module scaffolds bundle folder + `_category_.json` + landing page into one task** (T006, T013,
   T021, T027). Splitting them would leave a category folder with no documents in it, which breaks
   the autogenerated sidebar — the tasks say so inline.
2. **Almost nothing is marked `[P]`, deliberately.** The real parallelism is *within* a chapter
   task — the two reviewers always run together. Chapters cannot be written in parallel because
   later ones cross-link to earlier ones and reuse the Chapter 1.4 humanoid; marking them `[P]`
   would manufacture the forward references FR-016 forbids. This is stated rather than left as an
   omission.
3. **T020 is a gate, not a task.** Module 3's GPU question is settled *before* drafting, because
   discovering it afterwards wastes the drafting. If no GPU exists, the task requires recording the
   scope reduction as an explicit user decision.
4. **T037 (close the execution gap) is in Polish but flagged as not-optional.** Until it completes,
   every chapter is `drafted` and the honest status is "14 chapters drafted, N examples pending
   execution" — not "book complete".
5. A **content dependency table** names what each pivotal task produces and who depends on it
   (T004 terminology, T009 the agent-node skeleton, T010 the humanoid, T024 actions).

**Validated**: 38 task lines with 38 unique, strictly sequential IDs; 14 chapter tasks; 4 module
scaffolds; 8 build-check references; story labels present on every user-story-phase task and
correctly absent from Setup, Foundational, and Polish; zero unresolved template placeholders.

No chapter content written.
